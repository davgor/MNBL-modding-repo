# MMR-42 independent review (mission scenes from the generated map)

**The review.** One independent review of the implementation, the offline harness (`tools/Test-EncounterResolver.ps1` 28/28 at the time) and the first in-game run (46016). The reviewer:
- read the code;
- read the installed 1.4.8 / War Sails 1.2.8 code in IL: `DefaultSceneModel.GetBattleSceneForMapPatch` and its predicates, `MapScene.GetTerrainTypeAtPosition`, `GetMapPatchAtPosition`, `Location.GetSceneName`/`GetSceneCount`, the siege, hideout and naval raid openers, and `GetConversationSceneForMapPosition`;
- reproduced the harnesses (Test-EncounterResolver 28/28, Test-GraphValidation 71/71);
- ran a dense 20 × 20 sampling check of both compiled worlds' battle maps: 0 non-deterministic points;
- neither edited the repository nor started the game.

**Verdict before the fixes.** c1, c2 and c3 each met with fixes. All findings were fixed in one batch, except the ones decided otherwise below.

**Confirming results:**
- offline: `tools/Test-EncounterResolver.ps1` 35/35 (`evidence/world/mission-scenes-tests.json` and `.txt`); Test-GraphValidation 72/72; Settlements 22/22, NavalContent 15/15, SpawnPolicy 18/18, GeneratedCampaignDataset 60/60, SettlementPlacement 52/52, Playability 24/24;
- in game: runs 32960 (fixtures: field, settlement and naval missions, every settlement's live scenes) and 17596 (the periodic seam battle), summarized in `evidence/world/mission-scenes-report.json` (11/11 checks).

| 1 | blocker | Run 46016 failed: fixture `village_1` was a harbour village in the engine (its scene's drop-off gave it a port), but its intent had no port, so it took an inland prototype without the `naval_raid` level. | 2 | major | The lord's hall was checked as "any scene", but `Location.GetSceneName(n)` returns level n's scene, falling back to level 0's, which can be empty: a hall `[null, l1, l2, null]` passed but opens nothing at wall level 3. | `MissionScenes.Effective(scenes, n)` is the scene `GetSceneName(n)` opens. | 3 | major | The in-game probe looped to `GetSceneCount()`, which counts non-empty names, so it never read the level-3 hall. | The probe reads `GetSceneName(0..3)`, the effective scenes. Run 32960 shows every hall with its level-3 interior. |
| 4 | major | Missing catalogue fields (capacity, passages, hierarchy, return paths, patch-support evidence; tags counted file-wide, not per level). Slope and season not sampled. Biome not wired in game for compiled worlds. Doc sections and evidence missing. | **Catalogue:** scenes are parsed as XML. Each contract tag, prefix and script is recorded with the scene levels it is visible in (`byLevel`), so the raid points must be visible in `naval_raid`. The catalogue also records entity count, root entities, maximum depth, all path names, spawn points, siege-readiness scripts (`CastleGate`, `DeploymentPoint`, siege engine spawners, `WallSegment`), the contracts each scene meets where it is used (`usedAt`, `supports`), and per battle scene its capacity (spawn paths, entities) and classes. **Relief:** sampled from the compiled masks' landform plane (Mountain / ridge, Valley), which prefers scenes whose ground shows it (`WorldSurface.LandformAt`). **Season:** stated: every battle scene has winter terrain layers and the engine applies the campaign season. **Terrain context in game:** `GeneratedBattleTerrain.ContextSources` (biome and landform) is a handoff to MMR-45, stated as a limit. **Passages:** stated as a limit: the installed scenes have no passage scripts, and location targets are the prototype's location complex. Doc and evidence written. |
| 5 | minor | Contracts presented as complete: land raid not covered, siege controller entities not checked, port contract unverified; header comment stale. | **Land raid:** `land_raid` is an optional level (`StartVillageBattleMission` uses it when present; most village scenes lack it), inventoried. **Siege and port:** siege entity needs are inventoried, not required, and the port contract checks only installation; both stated in the doc. **Comments:** the header now lists the actual requirements. |

| 7 | minor | The 3×3 sampling can in theory miss slivers; add the dense check; break ties toward indices robust for every naval terrain. | **Dense check:** now a regression test, 6 × 6 points per cell on A and B, 0 misses (678,457 and 682,478 party points). **Robust indices:** used where a ship may read the patch while standing on land, the cells around every settlement's position, gate and port (`CellSamples.Robust`, 28 such indices installed). **Not taken:** robust as a general tie-break.
