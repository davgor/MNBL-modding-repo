### What the managed code actually establishes

- **Scene persistence is unresolved.** `Scene.Read` (`0x06000b73`) delegates to `IScene.Read`. `ScriptComponentBehavior.OnSceneSave` (`0x06000c55`) and `OnSaveAsPrefab` (`0x06000c57`) are empty overridable callbacks, not callable scene-save commands. Creating an engine Scene does not establish creation of an editor document. Full save/save-as/dirty-state/close/reopen needs its own proven route.
- **Undo registration is not an undo API.** Registration/deregistration (`0x06000c3c`/`0x06000c3d`) manipulate a managed list. They do not expose transaction boundaries or prove rollback. Official [navmesh documentation](https://moddocs.bannerlord.com/editor/scene-editor/nav_mesh/) explicitly warns that navmesh editing lacks Undo; a scene undo can affect an earlier scene operation. Use declared per-operation recovery strategies, including backups and reload, rather than claiming universal undo.
- **Runtime resource setters are not asset authoring.** Material's 56 methods include copies, resource lookup, shader/texture/name setters, but the bounded inventory establishes no durable asset save/import/publish route. Mesh edits, skeleton transforms, animation parameters and cloth reset likewise do not establish editable resource serialization or source reimport.
- **Terrain/navmesh coverage is partial.** Height/node data getters do not prove height writing, brush painting, resize, foliage painting or safe lifecycle. Navmesh prefab import/save, face enable/merge/separate and path points do not establish complete editor topology, rebuilding, road generation or river generation. The historical combined terrain-reader crash remains unresolved.
- **Generic command dispatch is only a possible route.** `Utilities.ExecuteCommandLineCommand` (`0x06000d63`) reaches `IUtil`; command completion and resource-modification checks exist. No specific save/import/publish command semantics follow from that fact. Across all 4,208 Engine method names, zero contain publish, two contain import (navmesh prefab), and two contain undo (registration). This bounded negative result does not establish absence in other assemblies or native code.
- **An editor tick route is concrete at the managed boundary.** `SceneEditorScreen.OnFrameTick` (`0x06000361`) calls `MBEditor.TickSceneEditorPresentation` (`0x06001b65`), which delegates through IMBEditor; generated wrapper `0x06000229` loads delegate field `0x040001b1` and calls Invoke `0x06000b4f`. The native pointer, safe hook, thread identity and behavior without a scene are not yet proven. `MBEditor._editorScene` is public static; SetEditorScene/CloseEditorScene/DestroyEditor are internal callbacks, not save commands.
- **Job scheduling still needs lifecycle evidence.** ConstructMainThreadJob enqueues jobs; RunJobs drains/invokes them. WaitJobs observes queue emptiness. The caller/pump and its behavior during transitions, teardown and no-scene states must be established before the bridge relies on it.

## Architectural direction (design, not observed behavior)

Use an out-of-process MCP host with local IPC to separate editor and shipping-game bridge modules. Keep protocol dependencies out of the engine CLR. Pin the host SDK/runtime and choose the bridge framework from the installed loader contract. Use explicit session/process/build/mode identity and generation-scoped handles, not arbitrary raw pointers. Discovery must report actual capabilities and unavailable reasons.

Use typed operations and paged resources plus a deliberate bounded scripting/command surface for advanced work. Batch operations need validation, budgets and attributable results. Engine jobs are queued onto proven lifecycle callbacks with backpressure; network/IPC threads never directly mutate engine state. Long work has persistent job identities, progress and result receipts. Timeout/disconnect does not mean rollback or cancellation; a native call already executing may have an unknown outcome.

Durable changes require dirty-state checks, expected revisions, dry-run changesets where meaningful, undo or explicit snapshot recovery, ownership boundaries and cold readback. Asset identity is GUID plus owning module and build, not only display name. Preserve published/source lineage. Shared resources and existing saves are protected by scope, not by silently limiting the requested feature breadth.

All subsystem families remain mandatory in the plan. Investigation may discover unsupported routes, but that does not permit closing a required feature as complete. Try another allowed route; if none succeeds, return a concrete blocker to the owner. One sprint is a scheduling constraint, not evidence that arbitrary engine internals can be controlled without investigation.
